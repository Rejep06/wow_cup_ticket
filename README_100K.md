# WOW CUP v6.1 — 1–2 билета до 100 000 ₽, не обязательно рядом

**Что исправлено:** раньше `BOOKING_SEATS=2` означал строго 2 билета. В v6.1 используются `BOOKING_SEATS=2` (максимум), `BOOKING_MIN_SEATS=1` (минимум). Бот сперва выбирает две самые дешёвые совместимые позиции, если их общая стоимость не превышает 100 000 ₽. Иначе выбирает одно подходящее место. Больше двух в одном заказе не выбирается. Места могут быть в разных рядах и секторах, но для одного заказа должны относиться к одному поставщику/сеансу. Если разные поставщики несовместимы, безопаснее оформить одно место, чем создавать неподдерживаемый смешанный заказ.

**ВНИМАНИЕ:** это экспериментальный помощник Playwright, а не официально поддерживаемый API клиент. Он НЕ гарантирует реальную бронь, потому что текущая разметка WOW CUP и исходящий POST `orders/create` ещё не проверены. При `CREATE_GUARD_STOP` или `order-validation-failed` бот обязан остановиться, а не симулировать бронь или автоматически повторять создание заказа. CAPTCHA, антибот-проверки и банковскую оплату выполняет только человек.

## 1. Настройте `.env` на сервере

В папке проекта:

```bash
cp .env.100k.example .env
nano .env
```

Заполните значения `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_IDS`, `BOOKING_OWNER_CHAT_ID`, `BUYER_FULL_NAME`, `BUYER_EMAIL`, `BUYER_PHONE`, `VNC_PASSWORD`. Владелец заказа должен быть конкретным chat ID; он получит сообщения об оформлении, остальные — только общие уведомления.

Обязательно должны быть:

```dotenv
BOOKING_SEATS=2
BOOKING_MIN_SEATS=1
BOOKING_ADJACENT=false
BOOKING_SECTORS=
BOOKING_MAX_PRICE_RUB=100000
BOOKING_MAX_TOTAL_RUB=100000
AUTO_BOOKING=true
AUTO_START_SBP=true
BOOKING_HEADLESS=false
CHECK_INTERVAL_SECONDS=10
POLL_JITTER_FRACTION=0.10
START_MODE=manual
```

`BOOKING_MAX_PRICE_RUB=100000` **не** означает, что бот может купить два билета по 100 000 ₽: действует и отдельный ОБЩИЙ предел `BOOKING_MAX_TOTAL_RUB=100000`. Если будет 1 билет за 95 000 ₽ и другой за 20 000 ₽, пара не будет выбрана. Одно место выберется при прочих подходящих условиях. Заранее выставленная цена — верхняя граница, не обязательная сумма покупки.

Возможны сборы, не предусмотренные первичным JSON схемы. Если сумма корзины не совпала с проверяемой суммой либо превышает лимит, автоматические клики прекращаются. Дополнительные услуги, страхование и сохранённые карты не выбираются автоматически.

## 2. Обновите работающий сервер

Если v6 уже установлен, **сохраните** `.env`, `data/`, локальную сессию и любые неоплаченные заказы. Перенесите изменённые файлы из архива поверх кода, не копируя поверх приватного профиля браузера. Добавьте в существующий `.env` минимум/количество и обновите бюджет/флаг соседства, как выше.

```bash
cd ~/yandex_tickets_checkout_v6_vps
chmod 600 .env
# Если переносите проект в новый каталог, перенесите data/ ПРИ ОСТАНОВЛЕННОМ контейнере.
mkdir -p data
sudo chown -R 10001:10001 data
sudo chmod 700 data
sudo docker compose up -d --build --force-recreate
sudo docker compose ps
```

Если старый бот был запущен в другом каталоге, сначала остановите старый процесс. **Нельзя одновременно запускать две копии с одним и тем же аккаунтом**. Не удаляйте `data/state.json` для повторного бронирования: он защищает от дублей. При незавершённом заказе сначала проверьте его через официальный интерфейс.

## 3. Первый ручной запуск (noVNC)

Не включайте постоянный `START_MODE=watch` до первого входа в браузер. Используйте SSH-туннель с ПК:

```bash
ssh -N -L 6080:127.0.0.1:6080 ubuntu@SERVER_IP
```

Затем откройте `http://127.0.0.1:6080/vnc.html`, введите VNC-пароль. В терминале на удалённом экране выполните:

```bash
python watcher.py --setup
python watcher.py --check
python watcher.py --test
python -m unittest discover -s tests -q
```

При `--setup` войдите в официальный Яндекс-виджет через этот Chromium; ручная CAPTCHA выполняется в том же окне. После входа нажмите Enter в удалённом терминале для сохранения профиля и выхода. `--check` лишь читает данные, `--test` проверяет Telegram.

## 4. Запуск 24/7 с попыткой перехода к СБП

Когда проверка завершена, в `.env` поменяйте **только** `START_MODE=watch`. Остальные значения из блока выше остаются. Выполните:

```bash
sudo docker compose up -d --force-recreate
sudo docker compose ps
sudo ./server/doctor.sh
```

Бот раз в ~10–11 секунд опрашивает данные без параллельных циклов. При первом подходящем сигнале сразу переходит к браузерной попытке. Это **не** разрешение сервиса на такую частоту и **не** гарантия отсутствия ограничений; при 403/429 применяются паузы, при CAPTCHA проверку решает пользователь, а не код. Не переключайтесь на секундный опрос и не используйте прокси для обхода блокировок.

Если виджет создаст и подтвердит бронь, помощник пытается открыть этап СБП. **Он не подтверждает банковский платёж.** Для оплаты откройте noVNC, увидьте официальный экран СБП и подтвердите перевод в своём банке. Если экран СБП не распознаётся, `ui.json` нуждается в проверенных селекторах. При `CREATE_GUARD_STOP`, `NEEDS_UI_ADAPTER`, `PAYMENT_UI_UNVERIFIED` или `order-validation-failed` нет гарантированной брони; новых заказов автоматически не создаётся.

## 5. Отладка и тестирование

Логи: `sudo docker compose logs --tail 100 wowcup` или терминал noVNC. Синтаксические тесты (локальные): `python -m unittest discover -s tests -q`. Для реальных Chromium тестов вне Docker задайте `TEST_BROWSER_PATH=/usr/bin/chromium`; в Docker Playwright поставляет Chromium в собственном каталоге, его путь может отличаться. Все тесты синтетические, без оформления настоящих заказов.

Если нужна доработка именно до **гарантированного автоматического открытия оплаты**, необходимо получить безопасно обезличенные `Method`, `Content-Type`, и структуру `Request Payload` первоначальных `POST /api/session-order-preview/` и `POST /api/tickets/v2/orders/create`, а также реальные селекторы/DOM корзины WOW CUP. Без них не стоит убирать защиту исходящего `orders/create` или заявлять об успешной интеграции.

Полная инструкция SSH/Tailscale, VNC и безопасности: `README_SERVER.md`. Не передавайте cookies, Authorization, CSRF, JWT, полный HAR или профиль браузера.
